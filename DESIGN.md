# Архитектура движка игры

## Структуры данных и алгоритмы описаны конкретно, по функциям

Битовые маски (Bitmasks):Числовые переменные (number), где каждый бит представляет флаг использования конкретного символа алфавита (применяется для оптимизации уникальности в рекурсивном переборе).

Кеширующая таблица (Memo Map):Структура Map<string, number>, связывающая префикс текущего секрета и битовую маску с количеством возможных валидных продолжений.

## Big O для всех четырёх указанных функций с обоснованием 

 - evaluateGuess: O(K) Два последовательных метода .reduce() по длине строки. Поскольку длина 6, операция выполняется за константное время O(1).
 - createDigitValidator: O(1) Замыкание инициализируется мгновенно; при вызове сложность равна вложенной функции isValidGuess
 - generateSecret: O(base + length) Алгоритм Фишера-Йетса делает один проход.
 - countPossibleSecrets: O(base!/(lengh-base!))*history, от системы счисление и длины секрета зависит - а собственно число комбинаций, накладывается история ходов. По идее мемоизация сокращает число повторных ветвлений.

## Принципы чистого кода с указанием, где конкретно применены

 - В generateSecret. Вместо скрытого вызова глобального Math.random(), источник случайности передается параметром (random: () => number). Это делает генератор предсказуемым.

 - (Single Responsibility Principle - SRP):
    isValidGuess отвечает только за валидацию строки,
    evaluateGuess — только за расчет быков и коров

 - (Encapsulation):
   Каррированная фабрика createDigitValidator скрывает реализацию валидации внутри возвращаемой функции-замыкания.
